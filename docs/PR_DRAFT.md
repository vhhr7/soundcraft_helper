# Draft — import external-WAV AAF as editable session data with a reusable core

Picture-editor AAF handoffs cannot currently be opened as editable SoundCraft arrangements (#40). This first-stage prototype builds SoundCraft sessions from a versioned rational-time interchange plan and exercises that same Rust library through a small CLI. A separate MIT-licensed pyaaf2 adapter reads a deliberately restricted AAF subset; it never constructs SoundCraft's session JSON.

The prototype preserves ordered/named audio tracks, individual SourceClip edits, gaps, source-chain offsets, full referenced WAV media and available handles, mono/interleaved stereo, and direct composition timecode/frame rate. It rounds absolute endpoints into samples to prevent accumulated edit-rate drift. Missing media, ambiguous compositions, unsupported editorial structures and source windows outside the available audio fail explicitly. It does not consolidate tracks.

Scope: reusable helper core plus a native development overlay on pinned SoundCraft 0.9.0 (`25d52c646aea780c8076ff966076f994ad256221`). File → Import → Session Data opens a thin preview UI; analysis is asynchronous, selected tracks are inserted atomically by `file.import_aaf`, and one undo restores the destination. The UI offers full-source collection on Save, absolute/relative time mapping, sample offset, media folder selection and explicit compatibility reports. No playlist replacement or resampling is offered.

Before upstream submission, move the same Rust constructor into a layered workspace crate and resolve distribution of the optional Python reader under upstream's pure-Rust policy. The development overlay keeps an external path dependency while working alongside the helper. A second, self-contained contribution export (`integration/upstream-aaf.patch`) now places the same core in `crates/interchange`, registers layer 3 and uses workspace dependencies. Its full CI passed in an independent checkout with installed VST3 directories unreadable to the test process: 1156 tests passed, one upstream benchmark ignored, no additional test filters, plus fmt/clippy/assets/layers/WASM. A normal run blocked while loading installed VST3 modules and was stopped; that environment is not certified. Optional reader packaging and pure-Rust policy still need maintainer agreement.

Validation performed:

- Rust unit tests for sample positions/durations/offsets/handles, model JSON roundtrip, stereo/names/order, invalid metadata/windows, overflow, and fractional-frame boundaries including 44.1 kHz.
- Python binary AAF tests including external Unicode/space/# paths, gaps, nested source offsets, composition selection, missing media, nonlocal locators, nonzero origins, embedded essence rejection and gain OperationGroup rejection.
- End-to-end CLI test checks sample values and full-source byte identity, refusal to overwrite, missing media and independent WAV metadata verification.
- Native SoundCraft 0.8.0, launched without audio: session inspection, loaded media, clip extension at both edges, save-copy and reopen. Screenshot inspected. Transcript and script included.
- `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked`, Python unittest suite. The native GUI was built and exercised. Full upstream `cargo xtask ci` remains pending; see graphical-import.md for the scope of current checks.

Not supported: OMF, embedded-media extraction, split stereo/channel selection, mixed sample rates/resampling, MXF/AIFF, gain/fades/transitions/effects, selectors, nested editorial sequences, timewarp, arbitrary slot origins, plugins, routing or automation. Non-audio slots and unsupported metadata are reported as outside scope. Producer-specific clip naming and gain/fade encodings need real-world fixtures; no interchange equivalence is claimed.

A real external-media AAF (22 tracks, 124 clips/sources) was also imported and inspected in SoundCraft after explicit filename relink; source slot edit rates are distinct from audio sample rates. All clip coordinates survived native save-copy/reopen. An independent read-only PTSL comparison against the open Pro Tools import matched all 124 placed-event starts/ends/durations, source offsets/windows, file identities and handles, with zero sample differences after normalizing the session origin. Clip-list totals differ by model (full sources plus edits in Pro Tools), and fallback track names/clip-name suffixes differ. Private API access was not enabled; public session EDL and original GetClipList JSON were used. The new native GUI import reproduces all 124 event coordinates and full-source lengths; loaded pools, save-copy, timecode origin, one-step undo/redo and menu invocation were checked. Long-session testing and classroom stability certification remain unverified. This is a tested base for further work and must not close the whole interchange gap.
